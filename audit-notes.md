# Мини-аудит (audit-notes)

Аудит выполнен в DeepSeek (промпт №4 из `prompt-log.md`) на черновике контракта, затем замечания разобраны и проверены тестами итоговой версии (`npx hardhat test` — 38 passing, `npx hardhat coverage` — 100 % строк).

## 1. Замечания DeepSeek и что сделано

| ID | Замечание DeepSeek | Решение | Почему | Тест |
|---|---|---|---|---|
| H-1 | Reentrancy-тест проверяет голый `.reverted`, причина маскируется | **Исправлено** | Тест должен доказывать работу guard, а не любой revert | «ReentrancyGuard блокирует повторный вход при выплате» — атакующий ловит ошибку и ставит `reentryBlocked = true` |
| H-2 | Покупатель не может отклонить некачественную партию → средства зависают после `Delivered` | **Исправлено** без арбитра | Сценарий задания: «иначе — возвращаются… при отклонении партии» | `rejectDelivery` (только покупатель, до дедлайна): «покупатель отклоняет партию…» |
| H-3 | `arbiter == 0` ломает разрешение спора | **Неактуально** — арбитр удалён | Арбитра нет в требованиях; мёртвая роль только увеличивала поверхность атаки | — |
| H-4 | Force-feed ETH (selfdestruct) ломает инвариант `balance == amount` | **Учтено** | Учёт идёт через `totalLocked`, выплачивается ровно `priceWei`; инвариант ослаблен до `balance >= totalLocked`. `sweep()` не добавлен — нет владельца, которому безопасно доверить излишки | «инвариант balance == totalLocked…» |
| M-1 | Нет верхней границы дедлайна | **Не исправлено** (ограничение) | Срок поставки — бизнес-решение покупателя, который сам создаёт партию и рискует только своими средствами | — |
| M-2 | Явно запретить прямые переводы (`receive` с revert) | **Учтено** иначе | Без `receive`/`fallback` прямой перевод и так ревертит; явный `receive` не защищает от selfdestruct | «контракт не принимает прямые переводы ETH» |
| M-3 | `markDelivered` не проверяет пустой хэш документов | **Учтено** иначе | Хэш спецификации проверяется при создании партии: `specHash != 0` → `InvalidParameter("specHash")` | «проверяет параметры…» |
| M-4 | `DEFAULT_ADMIN_ROLE` у покупателя — централизация | **Исправлено** | Админ ролей не назначается, роли неизменны; оплата на `immutable supplier` | «не назначает администратора ролей» |
| L-1 | Нет общего события `StateChanged` | **Не исправлено** | Задание требует 5 конкретных событий; каждое однозначно соответствует переходу | события проверяются через `.to.emit(...).withArgs(...)` |
| L-2 | Эмитить событие после `call` | **Отклонено — ошибка ИИ** | При неудачном `call` транзакция откатывается целиком вместе с событиями, рассинхрона нет; переносить событие = нарушать CEI | «если поставщик не принимает ETH, транзакция откатывается целиком» |
| L-3 | `nonReentrant` на `markDelivered` | **Не исправлено** | Функция не делает внешних вызовов и не работает с ETH | — |
| L-4 | Средства навсегда в контракте, если покупатель пропал после `Delivered` | **Исправлено** | Поставщик может забрать оплату сам после дедлайна | «поставщик может забрать оплату после дедлайна…» |

## 2. Дополнительно найдено при сверке с заданием

| Проблема | Риск | Исправление | Тест |
|---|---|---|---|
| Для несуществующего `id` статус по умолчанию `Created` (0) | Операции над несозданной партией | Карта `_exists`, ошибка `BatchNotFound`, `priceWei > 0` | «отклоняет несуществующую партию», «геттеры отклоняют…» |
| `fund()` без проверки дедлайна и без `nonReentrant` | Оплата просроченной партии; нарушение требования задания | `DeadlinePassed`, `nonReentrant` на `fundBatch` | «граница дедлайна» в `fundBatch` |
| Неоднозначная граница дедлайна | Одновременно доступны поставка и возврат | Поставка/оплата — `timestamp <= deadline`, возврат — `timestamp > deadline` | тесты «граница дедлайна» в трёх функциях |
| Неудачный перевод ETH | Потеря средств | `call` + `TransferFailed`, откат всей транзакции | «если поставщик не принимает ETH…» |
| Проверка входных данных | Некорректные партии и стороны | `ZeroAddress`, `SameParties`, `InvalidParameter(field)` | «Развёртывание», «проверяет параметры» |

## 3. Инварианты, проверяемые в тестах

- `address(this).balance == totalLocked` после каждой операции (форс-переводы ETH не моделируются);
- терминальные статусы `Released` / `Refunded` необратимы: повторные выплата и возврат ревертят;
- за одну партию выплачивается ровно `priceWei` и ровно один раз.

## 4. Известные ограничения

- Если поставщик — контракт, отклоняющий ETH, выплата невозможна (средства остаются на контракте до исправления на стороне поставщика). Решение — pull-платежи (`withdraw`), в учебной версии не реализовано.
- Поставка и качество подтверждаются сторонами вручную, без оракулов и арбитража.
- Статический анализ Slither не запускался; проверка безопасности — ревью ИИ и тесты.
